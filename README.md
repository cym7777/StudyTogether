## 在这台 Mac 上打开本地备份/维护版

1. 双击本目录的 `启动本地预览.command`。
2. 启动成功后自动打开浏览器；也可以手动打开 `http://127.0.0.1:8787`。
3. 关闭启动终端即可停止服务；下次启动仍使用同一份数据库。

如果电脑不允许双击，终端进入本目录后运行 `node server/local.mjs`。需要免费的 Node.js 24 或更高版本。在当前电脑上，启动脚本会优先使用已有的 Node，或者 Codex 自带的运行环境。不需要安装项目运行依赖。

这个网址只属于当前电脑，不是云端链接。不要把它发给异地成员当作可用网址。不要直接双击 `public/index.html`：`file://` 方式无法读写服务器数据库，会显示启动说明。

## 核心使用方法

- 首页点击三个名字之一。设置中可修改姓名、主题色和考试日期；修改姓名不会改变成员 ID。
- 每日三个板块顺序固定：今日完成情况、今日收获与总结、明日计划。
- 完成事项和计划逐条提交；新增不会覆盖已有任务。删除前确认，可点“撤销”或进入当天回收区恢复。
- 默认分类包括数学、英语、政治、专业课、其他和运动。运动与其他科目并列，可用于完成事项和明日计划。
- 总结停止输入约一秒自动提交。只有接口确认成功才显示“已保存”。失败时保留 IndexedDB 草稿，重新联网自动重试，或点“重新提交”。
- 总结出现版本冲突时会显示最新服务器内容，并保留当前草稿。你必须主动选择采用服务器内容或覆盖；覆盖前还会确认。
- 日期选择器可查看和编辑过去的记录。历史页提供月历及时间线，每页最多 32 天，点击进入完整记录。
- 昨天制定的计划自动展示在今天的完成板块上方。点击“标记完成”并确认后，才会添加到今天；昨天的计划仍保留。
- “打卡”定义为任意一个板块有非空内容。只有空白总结的日期不计打卡。今日未打卡时，连续天数从昨天向前计数；补记历史会重算。
- 全部业务日期采用 Asia/Shanghai。跨天不会挪动已有记录，进入“今天”后才开始写新一天。

不要清除浏览器站点数据后期待找回**未提交草稿**：已成功保存的记录在服务器数据库，待提交草稿在该浏览器中。任务弹窗提交失败时会保留输入，但尚未实现任务草稿跨浏览器重启恢复；关页前请复制文字或重试。

## 第二阶段新增功能

- 底部“统计”：累计/连续/最长连续打卡天数、累计/本周完成任务数量、最近七天情况、各科目分布；运动也计入。计划不算完成任务，软删除任务不算完成数量。
- 统计页“查看三人每周总结”：周一到周日的三人概览，切换成员查看每天的完成任务、完整总结、科目分布、关键词与待关注原文。上一周/下一周/日期选择可浏览历史周报。
- 关键词来自完成任务和总结的词频；待关注项来自含“疑问”“需要”“继续”等词的原句，以及本周最后一次制定的计划。不会推断问题是否解决，不会自动创建任务。
- 历史页新增关键词、科目、日期搜索，可组合筛选。关键词查找已保存的任务、计划和总结；删除的任务不出现在搜索结果中。结果每次最多 32 天。
- 个人页“分享今日打卡/分享这天的打卡”：生成三个板块的文字，一键复制后手动粘贴到 QQ 群。Day N 是截至所选日期的实际累计打卡天数，不是连续天数。复制被浏览器拒绝时可手动全选复制。未保存的总结必须先保存或处理冲突。

## 数据备份与恢复

设置页“导出完整 JSON”包括成员、姓名/颜色、考试日期、科目、所有日期的总结、任务、计划、删除状态及修改历史。本地导出来自数据库事务快照；云端按索引游标分段读取，整个过程检查版本一致，避免超出免费 Worker 单次 CPU 的大量序列化。期间有人修改就明确失败并要求重试，不生成不一致备份。未提交草稿不属于服务器备份，所以导出前要求先保存。

“导出 Excel CSV”列出业务记录，使用 UTF-8 BOM、引号转义与多行单元格，并将可能被 Excel 执行为公式的文字加上前置单引号。CSV 用于查阅，JSON 保留原文和全部字段并用于恢复。不要仅保存 CSV 作为可恢复备份。

恢复步骤：先导出当前完整 JSON 并确认下载文件已保存 → 选择旧 JSON → “检查并预览备份” → 阅读将补回和保留的数量 → 勾选已备份确认 → 输入“合并恢复” → 点击确认并再次确认。

默认只插入缺失任务、总结和科目，已有任务/总结（包括空总结、已删除状态）不会被旧备份覆盖。重复恢复不会重复插入任务；修改历史按内容和时间去重。恢复姓名、颜色和考试日期要额外勾选；预览后其他设备修改了设置，其版本检查会阻止旧备份覆盖该修改。

**这是合并恢复，不是把整个数据库回滚到过去。** 如果要取回已存在但后来改坏的总结，可从 JSON 的总结或修改历史中找到原文，复制回对应日期。全库回滚可使用停服后复制的 SQLite 备份，但应先另存当前数据库，防止丢失新记录。

JSON 恢复文件最多 16 MB，导出不截断历史。更大文件应使用 SQLite/数据库迁移，不要删除备份。云端恢复超过 40 个批量 SQL 语句会在写入前拒绝，避免突破免费调用限制；大型文件也可能触碰免费 CPU 上限，需本地恢复/SQL 迁移，不能升级付费套餐。CSV 不支持恢复。

建议每周手动导出一次 JSON，保存至少两份到不同设备/已有网盘；无需购买备份服务。

## 数据位置与本地数据库备份

本地服务器数据在 `data/study.sqlite`，浏览器不是唯一存储。历史修改快照在数据库 `revisions` 表中，删除记录保留在 `tasks` 表中。目前只有任务恢复界面；总结历史恢复界面尚未实现。

本地数据库备份：**先停止启动终端中的服务**，再复制整个 `data` 文件夹到另一处。恢复时先停止服务，另存当前 `data` 文件夹，再将确认正确的备份文件夹放回本目录；不要在服务运行时替换数据库。备份不是云同步。源码压缩包不包含私人学习数据库，数据请通过 JSON 或 SQLite 另行保存。

## 文件结构与维护

```text
public/          原生 HTML、CSS、JS 网页；无需外部字体、图表或 CDN
server/api.mjs   共享业务接口与校验
server/extensions.mjs  统计、周报、搜索、分享及备份接口
server/backup.mjs  备份验证、预览与事务合并恢复
public/features.mjs  第二阶段界面
public/reports.mjs  周报、分享、CSV 格式化
server/worker.mjs  已发布的 Workers 入口，DB 绑定不会暴露管理员密钥
server/local.mjs   本地 HTTP + SQLite 入口
server/sqlite.mjs  本地数据库适配及有版本的迁移执行器
migrations/      云端 D1 与本地 SQLite 共用的数据结构
tests/          核心自动测试与真实浏览器操作测试
wrangler.jsonc  已授权免费 Workers/D1 的部署配置（无管理员密钥）
PROGRESS.md     阶段状态与下一次继续工作的入口
```

修改功能先读 `PROGRESS.md`。页面文字与布局主要在 `public/app.mjs` 和 `public/styles.css`，业务逻辑在 `server/api.mjs`。更改数据库结构时新增迁移文件，不能通过删库重建丢弃现有数据。三个阶段继续使用此项目、此数据库结构。

核心测试：`node --test tests/*.test.mjs`。浏览器测试使用已有 Playwright（测试工具，不是运行依赖），运行 `node tests/browser.mjs`；可用 `PLAYWRIGHT_MODULE` 指定现有包，用 `STUDY_BROWSER` 指定已安装 Chrome。测试创建独立临时数据库，不修改正式 `data`。不需要付费服务。

## 云端状态

已采用用户授权的 Cloudflare Workers Free + D1，免费资源绑定已写入 `wrangler.jsonc`。OAuth 在系统钥匙串，不在源码。部署工具为固定版本开发依赖，本地运行仍无 npm 运行时依赖。

第三阶段进一步提供 320/390/768/1440px 布局检查、长文字防溢出、桌面快捷入口、无需后台的版本游标检查（无变化只读一个固定行）、一致分段云备份、安全响应头与禁止搜索引擎收录。没有 Service Worker 缓存 API，不会离线假报保存成功。

真实测试结果以 `TEST_RESULTS.md` 为准。两个独立浏览器通过公网操作 D1 不等于两台物理手机；本机已有代理下可访问也不等于大陆直连。三人应分别完成手机/QQ 验收后再以它为每天的正式记录工具。
